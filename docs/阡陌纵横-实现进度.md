## 5. 长期实现经验（永不清理）

### Structurize / 蓝图

- **`Blueprint.equals` 不比较方块内容**（只比 name / fileName / filePath / packName / 调色板大小 / 体积）。
  重建同名同尺寸蓝图会命中 `BlueprintHandler` 的旧渲染网格，表现为"内容没变、只是整体平移"，
  而且缓存 45 秒过期后又会自己变对。**任何重建之后必须 `BlueprintHandler.getInstance().clearCache()`**。
- `BlueprintPreviewData.setPos()` 要的是**蓝图 primary block 的世界坐标**，渲染端自己减 offset。
  生成器必须显式 `setCachePrimaryOffset(锚点 − 蓝图最小角)`，否则 `findPrimaryBlockOffset()`
  找不到唯一锚点方块时会回落到**蓝图中心**。
- `Blueprint.addBlockState()` 每次调用都会 `cacheReset(true)` 清掉 primary offset —— 设 offset 必须放最后。
- 结构包**只在进服时同步一次**；会话中途生成的蓝图必须随 payload 点对点下发，
  客户端写盘后重新注册包，否则建筑工具列表里搜不到。
- 预览用 `setRenderBlocksNice(false)`，否则 placeholder 被画成空气、填充被画成环境方块。

- Windows蓝图相对路径先统一分隔符，再严格比较包/路径/原锚点/原朝向；不能通过放宽身份校验来解决路径差异。
- 原生Blueprint便捷构造器将零号调色板设为blockSubstitution，未写入格不是空气。生成器必须显式初始化真实空气，并对实际原生对象及序列化结果逐格核对；不能只验证输入单元NBT。
- NbtUtils坐标编码不能假定为CompoundTag；持久化列表使用复合条目包装，按真实依赖验证写入与读取往返。
- blocksubstitution的实际处理取决于原生模式，Complete可能放置占位符；控制器预留最后写入，完成后统一迁移与守护，不能只凭占位符名称推断所有模式都跳过。

### NeoForge / 字节码

- 不要把 `Minecraft.player`（`LocalPlayer`）当实参传给声明为 `Player` 的方法：
  字节码验证器会加载这个客户端类，专用服务器直接 `BootstrapMethodError`，整个 mod 构造失败。
  要传就传 `Inventory` 之类的数据对象。
- `@EventBusSubscriber` 类必须至少有一个 `@SubscribeEvent` 方法，否则客户端启动即崩。
- **业务类不再内联轴判断**：`axis == X ? x : z` 只允许留在镜像方向选择、按轴选对象、`RoadSegment.endX` 的 Z 轴特例和持久化轴名四处，其余一律走 `RoadAxisMath`。取格写格的三种越界语义也不要合并：生成器抛异常拒绝生成、路口装饰静默跳过、联合图由调用方保证。
- **方法引用会触发整类验证**：`modEventBus.addListener(Network::register)` 生成方法引用时，JVM 要加载并验证 `Network` 的**全部方法**，`StackMapTable` 里出现的客户端类型会被真的加载——运行期的 `isClientSide` 守卫救不了（帧类型不是执行期才解析）。判断一个类是否 dist 安全，用 `javap -p -v` 只看 `locals = [` / `stack = [` 行是否含 `client/`。
- **网络通道必须两端对称**：`playToServer` 与 `playToClient` 都要在两端 `RegisterPayloadHandlersEvent` 里声明，握手比对的是通道名集合；只在客户端声明会让专用服务器被判「缺少此客户端需要的网络通道」而拒绝进服。服务端用空处理器声明即可（服务端收不到 S2C）。通道版本号每个 mod 只声明一次，两端复用同一个 `PayloadRegistrar`。
- **异常原文只能进日志**：玩家提示的参数不能是 `getMessage()`，否则「中文前缀 + 英文句子」。原因走「消息→lang key」映射，未登记降级为内部错误；`contains("budget")` 这类分支仍可继续按英文判断。

### BlockUI

- XML 只写 `color` 时，enabled / disabled / hover 会被设成同一个值，`setEnabled(false)` 视觉上无效。
  必须构造时 `setColors(text, disabled, hover)`。
- BlockUI 没有现成的文本输入弹窗；数字调整优先用 `-/+` 按钮，比自制弹窗省事也好点。

### MineColonies

- 权限绕过条件：玩家 rank 通过 → 否则 `hasPermissions(bypassMinPermLevel)`（默认 2）**且** `isCreative()`。
  生存模式的管理员**不**绕过，这是原版有意为之，不要补。
- 普通拒绝使用原版权限文案及置灰反馈，服务端仍复核；规划协商/具体失效原因另有通知。重复拒绝的 10 秒漂浮是已确认行为（见设计文档 §3.3 权限段），不要把旧说明当参考。

- Wilderness工单须先校验最近殖民地管理权限、建筑工和距离，再使用WorkManager可信加入入口绕过原生领地空间限制，保留onAdded钩子；不能把此入口当全局权限绕过。
- 控制器由服务端授权后开窗，必要时携带最小计划快照；客户端缓存缺条目不代表无权，也不能据此抢先打开原生空窗。
- 公民召回时的AWOL日志仅说明召回时实体不可用，不能据此确定原始消失原因。道路恢复只跟踪冻结目标与原工单，不因该日志额外删除、复活或传送公民。

### 原生工具与施工事务

- 共享格必须同时统一双方目标图与最终工图；仅给联合幽灵加显示优先级不能保证原生拼装或完成校验一致。预览副本也要继承道路身份，临时匿名计划会破坏按归属绑定的批准证明。

- 实际安装的WindowExtendedBuildTool可为final，优先用公开构造选择回调组合，不能仅凭refs分支假定可继承。
- 准备、确认施工和成功提交分开：目标冻结，令牌/玩家/维度/道路身份复核，成功保存applied后才落表。取消保留提案和旧applied；缺快照不猜测重建施工目标。
- Structurize即时队列不跨服务端重启持久化；恢复按已冻结目标、真实结果和原工单判断，回调需校验世界/会话代次，不能无条件重放。
- 实际应用快照是已建范围与拆除依据，未应用提案不能扩大删除范围；历史错误施工无法证明归属时保守处理。

### 状态与编辑解锁（阶段 4 的教训）

- **一个"能不能编辑"的判断会散在四处**：控制器面板按钮、面板按钮回调、客户端手势、服务端准入。
  每加一个解锁条件都要四处同步，漏一处就表现为"按钮亮着但点了没反应"。以后动这块先收成单一判断。
- **重规划有两条入口**：`rebuildPlannedRoad`（选点触发的预览请求）与 `handleConfigure`（建蓝图按钮）。
  改一处忘另一处，表现就是"功能时好时坏"。动重规划必须同时看这两条。
- **重建计划必须把两张表都搬过去**（已确认表 + 未应用 diff）。`RoadPlanBuilder.build` 产出的是全新对象，
  少搬一张，玩家的未应用编辑就会静默退回旧值——而且看起来像"面板数字莫名归零"。
- **显示语义决定写入位置**：面板要显示"未应用的改动数"，逐格编辑就只能写 diff；
  一旦同时写两张表，diff 永远为 0。
- **单向状态必须配退出路径**：`DRAFT` 只能通过建蓝图消费一次，工具关闭却没建时必须退回 `DRAFT`，
  否则玩家一次误操作就再也打不开原生工具（按钮永久置灰）。
- **不要给门禁新增持久化事实**：能用现有状态表达的就用状态（`state == DRAFT` 即可表达"从未确认过"），
  多加一个"曾经建成过"字段会让删改时到处漏（连 NBT 一起）。

### 渲染

- 内容变化不能只用edited数量去重；UP改DOWN可能数量相同而几何完全不同。
- 幽灵、回退框和索引框共用相机到实际体积的最近距离；固定世界方向的引导图形只做位置变换，不使用面向相机的旋转，不写入施工蓝图或生成持久实体。

- 规划批准与实际施工证明分开：显示状态不能作为权限证据；普通刷新不更换可答复请求，确认施工才冻结并消费本次批准。
- 索引查询发现的状态变化排队发布，避免查询中嵌套同步把新提案后面再覆盖成旧索引。

### 工具链（本机）

- 构建用build.ps1自动探测Java；本轮tools/jre成功完成构建与回归，旧“已损坏”的结论不再代表当前环境。
- `tests/run.ps1` 的 classpath 必须含 `src/main/resources`：随包单元清单 `units.json` 要经类加载器读，只放 `build/classes` 会抛 `Missing road unit resource`。测试若直接读资源（如 `RoadUnitDataRegression` 用文件路径），会掩盖这个缺口。
- 复用 ps1 脚本时注意文件头 BOM：`tests/run.ps1` 曾有两个 BOM 字节，导致 `$ErrorActionPreference = 'Stop'` 解析失败并静默失效（脚本仍跑完，只是不再早停）。编辑脚本前后核对开头字节。
- 回归计数按“Java 测试程序条数 + Python 校验”分开写：17 个 main 合计 906 条，`export_road_units.py --verify` 25 条，总计 931 条；把两者合并成“18 组”会掩盖哪个环节失败。
- 查依赖 API 读 `D:/PCL/workspace/refs` 里的源码，不要反编译 jar。
- 部署时不能仅凭Java进程名断言游戏仍运行；结合实例身份、窗口及目标JAR独占访问核对。EyeLib/H2锁占用先定位持锁者，不直接删缓存或存档。
- **`build.ps1` 只写 `dist/`，两个 `mods/` 目录不会自动更新**；验收前必须显式复制并核对三处同哈希。升级版本号会改 jar 文件名，**旧文件名那份必须删掉**，否则同一 mod 会被加载两次（同名覆盖才是安全情形）。部署目录里只应留一个本模组包。
- 会话记录在 `~/.workbuddy/projects/d-PCL-workspace/*.jsonl`，
  正文类型是 `input_text` / `output_text`（不是 `text`）。
- `tests/run.ps1` 必须在**仓库根目录**作为工作目录运行：`RoadUnitDataRegression` 用相对路径 `src/main/resources/.../units.json` 读单元清单，在工作区根跑会报 `NoSuchFileException`（此时前 18 个程序仍全绿，容易误判成代码缺陷）。
- 提案发布的失败门禁在 `road/common/RoadProposal.pack`（R7）：`RoadTemporaryPack.replace` 返回 `-1` 时不能继续写索引，否则规范快照与结构包副本不一致，表现为「预览是新的、实物是旧的」。
- 发布/重规划/收尾的 9 个入口顺序差异多为有意（`saveChecked` 短路、`setState` 三类位置、scope 边界、循环外合并广播）；重构时只收不变量，不把入口写成同一条流水线。
- 表结构合并（如 R4 六表合一、`lamps` 由布尔变三态）后，必须逐个检查**所有消费方**：兼容视图 `lampRows()` 会把 `CORNER` 算作「有灯」，而需要区分种类的调用方必须直接读 `row(int).lamp()`。R4-fix1 改了 `nearestLampRow` 却漏了同函数的门禁，直到 R7 人工验收才暴露。
- 排查「数据没写进去」之前先看持久化实测：本次直接解析 `rp_crossroads_roads.dat`（gzip NBT）就推翻了「灯结果不在 `rows`」的初判，把问题定位到读取口径。
- **同一条判定在两处出现，就要检查两边是不是同一个判据**：分层穿越的授权，施工侧用「带 actor」的 `canPlan`，规划侧用「只认 grant」的重载，结果是自己的路口按外来路算高度，多留了一截路灯。改法是抽出 `canPlanAsPlanner`，规划侧改用它；grant-only 重载留给自动避让暂存这种「就是要按有无批准决定策略」的场合，并在注释里写清用途。
- 文案分三层，缺一层就漏：**XML 静态 `label`**（改名普查只扫 `.java/.json`，`.xml` 的 `$(旧前缀)` 与干脆写死的英文都扫不到）、**窗口类 `Component.literal` 拼句**（枚举 `toString()` 直接上屏）、**过网预渲染**（服务端 `getString()` 把服务端语言固化到客户端）。回归要同时扫这三层，只看"提示是否走 `RoadNotices`"不够。
- 提示收口要分两层：**出口**（谁去发、哪个通道、去不去重）和**文案**（同一件事几条）。R8 只统一了出口，同一个门禁仍可能在不同入口各留一条文案；审计时按「触发条件 + 补救动作」分组，而不是按目录逐个文件看。
- 一次失败发两条，多半是两个去重键：生成器用 `generation:<原因>`、调用方用 `generate`，10 秒窗口各算各的。同一事件要么只让知道原因的一方发声，要么共用同一个去重键。
- 本地化键里会留下死键：改文案时换了新键却没删旧键，`consent.refused` 就是这样活了一轮。回归里加一条「源码字面量键必须存在于语言文件」能挡住漏键，但挡不住死键，删键仍需人工比对引用。
- **`Component.translatable` 的参数只接受 `Component / Number / Boolean / String`**，传枚举会在**构造时**抛 `IllegalArgumentException`。动作栏也走 `system_chat` 包，所以现象是「做完某个操作就被踢下线」，报错却是编码失败，很容易误判成网络问题。领域枚举（`CellType`、`State` 等）必须先转成 Component 或字符串。
- 提示装配必须有一层兜底：`RoadNotices.text(...)` 在参数不被接受时降级为字面量并记 error，不能让异常落到发包路径上——一次文案参数写错不该以掉线为代价。
- 「一根物品一个属性」只能有一条取值路径。同一个语义（这根魔棒绑了哪条路）曾经有手持、背包扫描、玩家级持久化三种取法，结果就是手持新魔棒却打开上一根的路。手势/面板可以有不同的校验宽严，但**决定「编辑哪条路」的来源必须唯一**。
