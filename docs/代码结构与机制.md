### 数据的四个层次

1. **选择与显示**：客户端A/B、工具上下文、索引和幽灵缓存，不能据此授权或证明已建成。
2. **道路提案**：RoadPlan的几何、pendingRows、RoadPlanningState。修改提案不改世界；DRAFT有效候选也会保存，不能把“预览”一概理解成纯临时对象。
3. **冻结施工事务**：RoadRepairSession的工图、主路目标、邻路局部更新、依赖、清空目标及授权证明。确认后不重新采样或重算替换执行目标。
4. **实际应用事实**：applied蓝图及appliedGeometry。用于既有道路约束、完成后的快照更新与拆除依据；未应用提案不能扩大删除范围。

## 2. 机制调用链（权威）

> 本节是 2026-10-31 函数级调用链普查的正文，权威的是**机制顺序与职责**；其中的 `文件:行` 是该时点的快照，R1–R7 增删代码后会漂移。定位实现请按**方法名**检索当前源码，不以行号为准。2026-11-05 已校正 2.3 / 2.8 / 2.9 / 2.11 中最易误导的引用与一处职责归属（详见各节）。

本节取代旧的「实际运行轨迹」。与旧版的差别：

1. 每条链标注**入口种类**（事件 / 网络包 / 物品手势 / 原生回调 / 定时轮询 / 数据驱动），不把"有方法"当成"玩家能用"；
2. 同一判定在多处出现时，标明**哪一处是权威、哪一处是镜像**（详见第 5 节整合清单）；
3. 新增 **2.12 不可达链与死代码**，把普查确认的死链从机制描述里彻底摘出去，避免后人照旧文维护已不存在的路径。

### 2.0 数据的四个层次（更新）

| 层 | 载体 | 位置 | 能否作为"已建成"的证据 |
|---|---|---|---|
| ① 选择与显示 | 客户端 A/B、镜像、工具上下文、幽灵缓存 | 客户端内存 | 否 |
| ② 提案 | `RoadPlan` 的几何 + **一张行状态表 `rows`**（`along → RowState{type, level, lockY, lamp, base}`）+ `planning` 的跨道路级表（`access` / `spanFloors` / `terrain` 等；`policies` 已删）；路口关系与成对授权已移入 `RoadManager` 的每维度 `junctions` 表 | 存档 + 同步快照 | 否（`RoadPlan.save()` 的提案部分） |
| ③ 冻结施工事务 | `RoadRepairSession`：主路冻结图、邻路局部更新、依赖、清空目标、`crossingGrants` | 会话 NBT（随计划持久化） | 否（"已确认"，不等于"已完成"） |
| ④ 实际应用事实 | `applied_<uuid>.blueprint` + `appliedGeometry` + `appliedBounds` | 存档蓝图文件 | **是**（唯一依据） |

> ②层的 6 张表曾是最大的结构债（同一行的类型/手改/基线/锁定/灯分散在 6 处，清理语义互不相同）。**R4 已合并为零张额外表**：六表收进 `rows` 一条记录，`pendingRows()` 改为与 `applied` 快照行表比较得出的派生量，手改/锁定由 `level` 表达，灯由 `lamp`、无路口基线由 `base` 表达，因此原来那条「六表清理语义不一致」的结构债关闭。

```text
   └─ 生成 → 保存 → 发布 → 索引 → 同步（见 2.11 的流水线，当前此处第 3 号副本）

└─ 共同序列：RoadBlueprintStore.preserveBuilt:154 → RoadBuildWatcher.stop:124

```

- 编辑结果**不改世界**，只改那一行的 `type`；服务端重新生成蓝图并回推预览。
- 行状态只有一张表：`rows[along] = {type, level, lockY, lamp, base}`。手改 = `level == MANUAL`，锁定 = `level == LOCK` + `lockY`（路面高度），灯结果 = `lamp`，无路口基线 = `base`。
- **“待 Repair”与“丢失”都是字段差**：`pendingRows()` 是当前 `rows` 与 `applied` 快照行表的差（比 `type`）；`lostRowCount()` 是同一对表里**丢了 `MANUAL`/`LOCK` 等级**的行数（比 `level`）。`pendingRows()` 只算当前 `[A]..[B]` 范围内的行，`lostRowCount()` 不设范围——被缩短丢弃的手改/锁定等级行也计（与设计文档 `dropped` 口径一致）；两者互不推导，纯自动行被缩短丢掉两个数都不进；从未建成的道路没有 `applied`，因此恒为空（否则自动规划出的坡度会被全算成待检修）。客户端没有快照，改由同步包里的 `appliedBuilt`／`appliedTypes`／`appliedCount` 投影做同一份差分。
- 沿街道路缩短后的越界行由 `pruneOutOfRangeRows()` 裁掉（旧名 `applyPendingRows`，R4 起 `pending` 已不再需要“合并”，只剩裁剪）。

## 4. 旧入口、已知差异与实现边界

- 当前基线与部署：源码即 0.2.0-beta.1（基于阶段 7 的 `9de22c0`，含 R1–R10 与各修复轮（含 R5-fix1/fix2、R6-fix1/fix2/fix3、R7-fix1、R8-fix1/fix2/fix3、R9-fix1、R10-fix1/fix2/fix3）及收尾清理，dist、客户端与服务端为同一 JAR（`rp_crossroads-0.2.0-beta.1.jar`、`470,002 B`、sha256 `E2D9AB6CF075B5BA…`、协议 13；mod 为「阡陌纵横」、modId `rp_crossroads`、包 `com.YLFXM.rp.crossroads`、结构包 `Crossroads`，已提交，提交号以 `git log -1` 为准）。三处同哈希已部署；运行中的实例需重启才加载新包。版本号与内容不必对应，不能只按文件名判断；历史由 CHANGELOG/Git 承担。
- ModRegistry只注册物品和创造分页；当前不存在已注册的自定义道路控制器方块。正式控制器来自MineColonies。
- ClientNativeBuildTracker只用公开updateBlueprints定位generated，不自动选蓝图；WindowRoadRepairBuildTool使用公开回调组合原生窗口。
- 受控工具当前仅Complete/Pretty/Survival；旧Paste/面板直接刷块/旧A工单不是当前公开施工机制。R1 已把旧直接施工整类（`RoadQuickBuilder`、`RoadWorkOrderService` 等）删除，不再有「旧类存在但入口失效」的情形；判断入口一律以第2节调用链为准。
- 状态回退只有一个依据：持久`RoadRepairSession.previousState`。首次未确认就取消回DRAFT，已确认的取消/未完成回PLANNED并保留冻结中断。旧的内存标记`RoadBuildWatcher.FROM_DRAFT`从未接线（零调用、恒空），已随R2删除——不要再引入第二处“谁改回DRAFT”的判定。
- Surveyor未绑定有野外视图，并非始终空表；道路控制器面板最终要求MANAGE_HUTS，Shift绑定/列表查看与管理的门槛要分开。
- 服务端generated按canPublish覆盖DRAFT/PLANNED/BUILDING等有效状态，不只有正在BUILDING；客户端点对点传送也没有取消Structurize进服整包机制。当前设计/说明不能承诺绝对的文件级私有同步。
- Config含wildernessWorkerMaxDistance=256、maxGeneratedBlueprintVolume=1048576；`creativeInstantBuild` 与 `roadFillBlock` 已随旧直接施工整类删除（R1）。灯距运行实现≤1不生成，UI范围1–8，配置允许0。
- 新共同平台的施工证明依赖双方目标及各自实际图。共享台阶优先必须同时写入两路目标，不能仅改幽灵显示；0.1.7 已按此实装并通过阶段7人工验收。
- 路灯单元解析仅支持当前经典street资源组，当前最大道路长度256与预览64距离独立。多风格、升级、可配置渲染距离及面板视觉优化仍非完成项。
